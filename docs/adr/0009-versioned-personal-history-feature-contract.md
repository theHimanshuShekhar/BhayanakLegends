# Version the Personal History parity feature contract

Status: Accepted; supersedes ADR-0001.

ADR-0001 selected the `loltrends` package as the app's extraction library, but
LoLTrends does not currently publish an installable wheel. Waiting for that
wheel would block the companion app even though the app needs only a small,
well-defined checkpoint subset and already keeps population findings in the
Findings Pack. The app therefore owns a slim extractor for this subset. The
unavailable wheel no longer blocks the app because this extractor is bounded by
an explicit parity contract, while every population-level conclusion remains
owned by the Findings Pack. When a wheel becomes available, replacing the
implementation is safe only if it preserves this contract or increments its
version.

## Normative contract: `loltrends-parity-v1`

The contract covers exactly these Personal History fields. Timeline snapshots
use the latest frame at or before each checkpoint. A populated frame with a
timestamp at or after 600,000 ms is required to prove the timeline reached ten
minutes before any `cs10`, `level10`, or `gold_diff_10` value may be emitted;
without that proof, those values are missing even when earlier frames exist.
After ten-minute reachability is proven, the latest frame at or before 600,000
ms supplies the 10-minute values, while 15- and 20-minute lookups remain
independent. Gold medians include every participant present in the selected
frame (including the local participant), and non-numeric gold values are
excluded from the median pool. Missing frames, participants, or non-numeric
local gold produce a missing value rather than a proxy or an invented value.

| App field | LoLTrends field | Unit | Definition |
| --- | --- | --- | --- |
| `cs10` | `total_cs_at_10m` | minion kills | `minionsKilled + jungleMinionsKilled` at 10m; absent counters count as zero |
| `level10` | `level_at_10m` | champion levels | local participant's level at 10m; absent level counts as zero |
| `gold_diff_10` | `gold_vs_median_10m` | gold | local `totalGold` minus the all-participant median at 10m |
| `gold_diff_15` | `gold_vs_median_15m` | gold | local `totalGold` minus the all-participant median at 15m |
| `gold_diff_20` | `gold_vs_median_20m` | gold | local `totalGold` minus the all-participant median at 20m |

`backend/src/bhayanak_legends/extract.py` may emit only the five App fields
above (plus the match identity fields returned by `parse_match`). A same-named
field is not interchangeable with a differently defined feature: for example,
lane-only CS is not `cs10`. Pack population data may join a personal value only
when its `feature_contract` declaration names the matching LoLTrends feature,
as described in `docs/CONTRACT.md`.

## Parity-fixture obligations

Both repositories carry the same synthetic timeline input and hand-computed
expected outputs for every field and participant. The expected values are an
independent source of truth, not values generated by the extractor under test.
Each repository's enforcing test must fail if a field formula, unit, checkpoint
lookup, missing-data rule, or field registration drifts. A definition change
requires updating both fixture suites and bumping `loltrends-parity-vN` in one
coordinated change.

The ten-minute reachability condition above clarifies the existing
missing-data rule; it does not change a field definition, formula, unit, or
checkpoint lookup. The parity contract therefore remains
`loltrends-parity-v1`, and the shared parity fixtures remain valid.

The LoLTrends-side enforcement artifact is closed in
[theHimanshuShekhar/lol-trends#29](https://github.com/theHimanshuShekhar/lol-trends/issues/29),
commit `dd200b7`. Its `tests/test_companion_parity.py` pins total CS@10,
level@10, and gold-vs-median@10/15/20. This repository mirrors those inputs and
expected values under `backend/tests/fixtures/parity/` and enforces them in
`backend/tests/test_parity.py`.

## Consequences

- ADR-0001's package dependency is no longer a prerequisite for app startup;
  the app's extractor remains intentionally small and auditable.
- Extraction and benchmark joins must stay inside the versioned subset. New
  same-named proxies are prohibited; new features require a contract version
  and parity fixtures on both sides.
- Post-game habits are emitted only when an exact extractor and threshold exist.
  Until one does, the digest carries no habit rows and the UI says outcomes are
  unavailable; it never fabricates `n/a` verdict rows.
- ADR-0003's tier and phrasing discipline is unchanged: this decision changes
  feature provenance, not the wording rules for findings.
